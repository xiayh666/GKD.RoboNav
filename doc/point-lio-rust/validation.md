# Rust 实现场景测试（2026-11-11）

这是修正前版本的历史记录；最新实现和仍然失败的压力测试见
[correction.md](correction.md)。

本轮仅增加测试和回放适配，不修改滤波或地图算法。场景均为合成数据，
不能代替真实雷达验证。阈值是本轮明确设定的检查条件，不是行业标准。

运行功能测试：

```sh
cargo test --release -p point-lio --test usability -- --nocapture --test-threads=1
```

| 场景 | 结果 | 实测 |
|---|---|---|
| 含噪静止 60s，默认 100000 体素容量 | 通过 | 最大位置误差 0.020259m，最大姿态误差 0.006286rad，最小匹配 996/999，最终 683 体素 |
| 相同静止输入，容量限制 300 体素 | 失败 | 最大位置误差 0.363425m，最大姿态误差 0.064669rad；要求 <0.15m / <0.05rad |
| 3s 平滑加速旋转，正常量程与裁剪量程对照 | 失败 | 正常组最大姿态误差 0.103185rad，超过 0.05rad；裁剪组 0.108539rad，饱和屏蔽 532 轴次 |
| 单地面，运行后引入 x 轴 0.2m/s² 加计误差 | 退化刻画通过 | x 漂移 0.780142m，z 误差近零；仍有 47595 次匹配，说明有匹配不代表全部方向可观 |
| 雷达空回波 0.5s 后恢复 | 通过 | 恢复首帧匹配 1663 点，最终位置误差 0.036367m |

静止噪声：点坐标各轴 1cm 幅度的确定性三角函数扰动；IMU 角速度
各轴 0.001rad/s、加速度各轴 0.02m/s² 幅度扰动。它不是随机白噪声。
默认静止场景累计 600 帧、每帧 999 点、IMU 200Hz。场景直接生成若干
平面的坐标，没有模拟真实扫描可见性、遮挡和动态物体。

默认地图容量复测通过，300 容量结果说明小地图压力场景下的累计误差；
现有证据不能把失败唯一归因到某行代码。正常量程旋转也失败，因此
不能将旋转误差完全归因到饱和处理。算法保持原样，失败断言保留。

## 处理耗时

```sh
cargo test --release -p point-lio --test usability processing_time_by_scan_size -- --ignored --nocapture --test-threads=1
```

主机 Intel Core i5-13500HX，release 构建，单个估计器顺序处理。
每个规模先处理一帧建立地图，再测 5 帧；计时包含排序、逐点滤波、查询、
地图更新和结果构造，不包含生成输入数据。测量时无其他本任务数值测试并行。

| 每帧点数 | 中位耗时 | 最小～最大 | 5 个样本是否全部 <100ms |
|---|---|---|---|
| 1000 | 26.351ms | 26.173～27.149ms | 是 |
| 10000 | 258.096ms | 247.852～270.993ms | 否 |
| 20000 | 509.290ms | 501.680～509.599ms | 否 |

每个点时间均匀分布，地图规模与场景生成器固定；不是所有场景的性能上限。
5 次样本也不是长期抖动或严格实时保证。当前实现不能在这些 1 万/2 万点
配置下满足 10Hz 输入，不应直接宣称可用作实车实时里程计。

## 当前结论

默认配置短静止/含噪静止和短时缺失恢复可以工作，但扩展测试发现地图
容量压力下漂移、旋转误差和处理速度问题。原先 13 项通过不能视为工程
可用性的证明。官方完整程序同文件对照已完成，结果见
[official-comparison.md](official-comparison.md)。
