# terrain_map 设计讨论

## 已确定

- 目标平台为全向轮底盘；需禁止不满足车体净空的区域和不可跨越台阶。
- 独立纯 Rust 库，目录 src/terrain_map，Cargo 包名 terrain-map。
- 在线建图，不依赖先验点云；接收 Point-LIO 等里程计系统的位姿和点云。
- 地形地图与里程计内部匹配地图独立维护；不依赖 ROS 类型。
- 普通 CMake 调用 Cargo，加入现有 ros2 容器 colcon 构建。

## 本轮范围

初始 T1 仅创建空库与构建入口。T2 实现同步体素更新、私有 Rayon 帧内并行、Tokio 有界调度、完整 COW 快照和人工标注管理；不改变 Point-LIO 算法。地形特征和自动隧道分析仍待后续阶段。
工作区成员增加，Cargo.lock 同步；移除成员及目录可回退本次骨架。

## 待讨论的建议（尚未实现或定案）

数据流：带坐标系与时间语义的点云/位姿 → 局部三维地图 → 地表提取与几何特征 → 机器人通行性评估 → 导航地图。
首先明确机器人类型、重力对齐坐标系、雷达安装及自体过滤、地图范围/分辨率和多层地表需求。
三维存储与二维/多层地表视图可以分层，但需先确定是否必须通过射线清除动态占用，以及未知空间如何表达。
坡度、粗糙度、台阶等几何量与机器人相关的通行判断应分别定义；观察不到的坑洼不应直接视为地面。

风险：逐点变换后的世界点云不足以完整表示每束射线的起点和时间，若做射线清除，需要明确额外输入；不可凭空假定所有点来自同一时刻传感器位置。

## 已收到的机器人约束
需要区分地形几何、车体三维碰撞空间和轮式底盘可跨越性。不能只凭坡度判通行。具体车体外形/高度、离地间隙、轮径、台阶和坡度限值尚未提供；待讨论时确定。全向运动也不代表任意朝向具有相同的通过条件。

## 隧道禁行约束
用户明确：场景中存在隧道，禁止从隧道通行，即使其几何净空和地面条件允许。禁行规则需独立于几何通行性，最终输出必须保留禁行原因。尚未确定隧道识别来源：人工/外部标注、在线几何检测，或两者结合；不能把任意头顶遮挡直接等同隧道，也不能把未识别到隧道当作已证明非隧道。无需先验点云与允许独立区域标注是两个不同问题，是否接受标注待用户确定。

## T2 执行架构

地图以8×8×8空间块组织，输入每条回波的世界系采样时刻原点与终点。Rayon每256条射线并行生成占用/空闲位图，位图按块OR合并，命中优先于空闲，每格每帧只累计一次，避免并发顺序和点密度改变分数。提交前校验输入、单束步数、更新体素预算及地图块容量；失败不修改状态。地图中心移动和观测过期会使区域重新未知。

同步Mapper独占私有CPU池和地图。Tokio任务只组织命令，逐次await一个spawn_blocking；不让几何循环阻塞异步线程。实际CPU并行发生在Rayon池，cpu_threads默认2。点云与标注走同一有界FIFO，try_submit满时返还输入，标注确认与帧确认均以提交后结果为准。

块Arc提供写时复制；完整快照通过watch发布，区分总版本、地图版本及标注版本。地图块上限不包含暂存/历史快照峰值内存；慢读者应释放旧快照。运行层不创建全局Tokio runtime，支持current_thread，关闭时拒收新请求并排空已接收命令。单独丢弃回执不撤销请求。

当前不输出地形可通行结论。TunnelHint只是提示区域；Forbidden点查询不包含机器人外形膨胀，false不代表安全。地图中尚未保留拟合所需的细粒度表面统计，后续地形层将扩展其输入和表示。
